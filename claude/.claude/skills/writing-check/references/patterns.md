# 直し方の例

`~/.claude/rules/japanese-writing.md` の各項目を、どう直すかの例で示す。例の多くは natural-japanese（coji/natural-japanese）と yomiyasu（nanaism/yomiyasu）の規則から採った。

## 内容を足さない

議事録の一文を直す場合。

- 元の文: 佐藤さんが在庫回転率を使う案を出し、鈴木さんも賛成した。最終的にどう決まったかは次回また相談することになった。
- 誤った直し方: 在庫回転率に変更する方針で合意した。具体案は田中が7/18までに作る。
- よい直し方: 在庫回転率を使う案が佐藤さんから出て、鈴木さんも賛成した。決定は次回に持ち越した。

誤った直し方は、決定、担当、期日が元にない。確信の度合いも「相談する」から「合意した」に上がっている。

言い回しだけを変えるときも、推量の強さは元のままにする。

- 元の文: このツールを使用することで、作業効率を大幅に向上させることができると言えるでしょう。
- 直した文: このツールを使うと、作業の効率は大きく上がるだろう。

見出しや冒頭の要約では、本文の条件を落とさない。本文が「年間契約で、月の利用が100回を超えるユーザーは割引の対象になる」なら、冒頭を「よく使うユーザーは割引になる」にしない。

## 読み手が何のことか分からない言い回し

| 種類 | 例 | 直し方 |
|---|---|---|
| 中身が見えない比喩 | この変更はチームの重心を移す | 前後から読み方が一つに絞れるなら「担当の範囲を変える」のように書き、どう読んだかを報告に添える。絞れないなら直さずに聞く |
| 名前のあるものの言い直し | 支払いの済んでいない注文が宙に浮く | 支払い待ちのまま残る、のように起きることを書く |
| 擬人化 | 設定ファイルが育っていく／データが語っている | 設定ファイルに項目が増えていく |
| 英語の逐語訳 | 低くぶら下がった果実から取る／真実の源／一級市民として扱う | すぐできるものから手を付ける |
| 語の組み合わせのずれ | 期限が終了する／リスクを踏む／知らせが来る | 期限が切れる／リスクを負う／通知が来る |
| 話し言葉の持ち込み | ログを吐く／サーバーが死ぬ／キューに投げる | 出力する／止まる／渡す |
| 動作の名詞化 | 重複登録が起きうる点の対処／権限の整理は未着手です | 同じ利用者が二重に登録されないように直す／権限を誰に付けるかは、まだ決めていません |
| 動詞を名詞にした言い方 | 結果の確かめ／文章の突き合わせ | 結果の確認／文章を照らし合わせる |
| 大げさな名詞 | 決まりを「契約」、確認を「ゲート」、一覧を「台帳」と呼ぶ | 実際の役割の語で書く。正式な名称なら残す |

直すときに守ること。

- 使ってよいのは素材に書いてあることだけ
- 硬い漢語に置き換えない。「育っていく」を「拡充される」にすると別の不自然さになる
- 評価の向きや強さ、「うっかり」「ようやく」のような含みを変えない

直さないもの。

- イメージが具体的に浮かび、ふだんの仕事の文章でも使う言い方（目を通す、手を打つ、腰を据える）
- 定着した慣用句、発言者の言葉の引用、その分野で定着した用語
- 同じ文の中に中身が書いてある比喩（バックアップを毎晩取っているので、データは守られる）

## 打ち消し

| 種類 | 例 | 扱い |
|---|---|---|
| 先回りの打ち消し | ただし、CI を入れれば自動的にバグがなくなるわけではありません。 | 文ごと削る。削ると次の文がつながらないなら残す |
| 打ち消してから言い直す | コードレビューは、粗探しの場ではありません。設計の意図をチームで共有する機会です。 | 打ち消しを削り「コードレビューは、設計の意図をチームで共有する機会です。」にする。新しい言葉は足さない |
| 語の意味を絞る | ここでいう「軽い」は、ファイルの大きさではなく、起動するまでの時間のことだ | 残す |
| 誤解を正す | 原因はキャッシュではなく DNS の設定でした | 残す |
| 注意を促す | 環境変数に入れたという理由だけで、秘密が守られるわけではありません | 残す |

## 調子を強める言葉

削っても文が同じことを言えるときだけ削る。言い換えない。

- 設定ファイルの書き方を徹底的に解説する。→ 設定ファイルの書き方を解説する。
- 圧倒的に多くの利用者 → 多くの利用者。「非常に多くの利用者」にはしない
- 「〜の放棄に他ならない」から「他ならない」だけを削ると文が壊れる。壊れるなら残す

問いを短い文に割って決め台詞で締める形は、演出を足している。

- してはいけない例: 「どの設定が使われているのか。どこを直せばよいのか。手がかりは何もない。」

## 太字のラベルとコロン

コロンのあとが値か、説明の文かで分ける。

- 値のラベルは残して太字だけ外す: `- **期限**: 11月末` → `- 期限: 11月末`
- 説明の文のラベルは文に溶かす: `1. **応答速度の低下**：ピーク時に3秒を超えた。` → `1. 応答が遅くなり、ピーク時に3秒を超えた。`
- ラベルにしかない語は落とさず文に入れる: `- **鍵と名札の返却**：帰る前に受付に返却する。` → `- 帰る前に鍵と名札を受付に返却する。`

## 読点

外す読点。

- 短い主題の直後で間を作るだけのもの: これは、／課題は、／1つ目は、
- 「AではなくB」の「なく」のあと
- 見出しの中

残す読点。

- 誤読を防ぐ: 店長は、慌てて逃げた客を追いかけた
- 主題のあとに別の動作主が続く: 会議では、担当者が説明しました
- 長い主語や節のあと、並べた語句の間、条件・逆接・理由の切れ目、文頭の接続語のあと

## 括弧

- 確認したいのは2点（配送料の負担、返品の受付期間）です → 確認したいのは、配送料の負担と返品の受付期間の2点です
- 会議室を予約した（総務の木村さんが手配。利用料は無料）→ 総務の木村さんが会議室を予約した。利用料は無料だ
- 残す括弧: 略語の正式名称、短い言い換え、主張を支える数値や出典（検索流入が減った（71,200件、前月比 -8%））

## 見出し

- 「〜について」「背景」だけでは中身が分からない。本文にある言葉で、その節に何が書いてあるかが分かるようにする
- 「AではなくB」の形にしない。B の側だけを書く
- 「jq とは：使い方」→「jq の使い方」
- 全部の見出しを同じ形にそろえない。同じ形が並ぶと、それ自体が機械的に見える
- 見出しで本文より確信の度合いを上げない。本文が「予定」と書いていることを見出しで断定しない

## 構成を直すとき

- 箇条書きと地の文の入れ替え、段落の組み直し、見出しの数や順序の変更は、頼まれたときか、直さないと読み手が取り違えると具体的に言えるときだけ行う
- 同じ種類の変換を全項目に当てない。元の文書にあった自然な不揃いが消え、かえって機械的に見える
- 文を分けるとき、元にない接続の言葉（しかし、その結果、そこで）を足さない
- 短くすること自体を目的にしない。文を分けたり列挙を開いたりして字数が増えるのは正しい結果
