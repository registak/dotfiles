# writing-check

ルールは `~/.claude/rules/japanese-writing.md`。このスキルは、そのルールを1本の文書に当てる手順を定める。

書いた本人は自分の書き癖に気づきにくい。数えられるものは `scripts/check.py` に数えさせ、数えられないものは段落ごとに問いを当てて確かめる。

## 手順

### 1. 読み手を決める

- 読み手、使われ方、社内の資料か社外発信かを1〜2行で示す。会話から決まらないときだけ聞く
- 社外発信なら `references/external.md` を読む。社外発信向けのルールはそこにある
- 素材を確かめる。この文書の元になる会話、メモ、資料はどれか。素材にないことは書かない

### 2. 下書きを手元に置く

- 新しく書く文書は、書き出し先へ直接書かず、スクラッチパッドに Markdown で下書きする
- 既存の文書を直すときは、直す前の文書をスクラッチパッドへコピーしておく。手順5の比較に使う
- 素材が会話にしかないときは、使った事実を箇条で書き出したファイルをスクラッチパッドに作り、素材として使う

### 3. 数える

```
python3 ~/.claude/skills/writing-check/scripts/check.py <下書き> --audience internal|external --source <素材や元の文書>
```

- `--audience` は社内の資料なら `internal`、社外発信なら `external`
- `--source` は複数指定できる。下書きにだけある数値・英字・カタカナ語が挙がる
- 指摘は疑い。1件ずつ、直すか、理由をつけて残すかを決める。残す理由は「引用」「公式の文言」「定着した言い方」「値のラベル」など一言でよい
- 指摘が0件でも手順4は省かない。スクリプトが見ているのは表面だけで、比喩、直訳、足した内容はほとんど検出されない

### 4. 段落ごとに問う

見出し、箇条の1項目、段落を上から順に、次の問いに当てる。通して読むだけだと「もう読みやすい」と判断して見落とすので、1つずつ見る。直し方の例は `references/patterns.md` にある。迷ったときに読む。

1. この語が指している具体的なものを、素材にある事実や名前で言えるか。言えるのに広い言葉や比喩で書いているなら、その事実や名前で書く
2. 英語に訳し戻すと、決まった言い方を1語ずつ置き換えた形になっていないか
3. 動作を名詞にまとめた箇所を「誰が何をどうする」の文に書き直すと、中身がはっきりするか。はっきりするなら書き直す
4. この名詞と動詞の組み合わせを、ふだんの会話で言うか
5. 素材にない事実、数値、評価、方針が入っていないか。確信の度合いは素材と同じか。手順3で挙がった語は1つずつ素材と照らす
6. この段落は中身があって置かれているか、形を整えるために置かれているか。後者なら削る
7. 前後の段落や項目と、書き出しや組み立てが同じ型になっていないか

文書全体では次を見る。

- 見出しだけを順に読んで、何の節かが分かるか
- 社内の資料なら、節ごとに書式がそろっているか。列挙の観点がそろっているか
- 社外発信なら、話題ごとの字数が均等になっていないか

### 5. 直して比べる

- 自分がこの場で書いた下書きは、承認を待たずに直す
- 人が書いた文書や公開済みの文書を直すときは、先に「いま／案／理由」の一覧と、直さないものをチャットに出し、承認を得てから直す
- 直したら `check.py` をもう一度実行する。直したことで新しい指摘が出ていないかを見る
- 同じ指摘が2回続けて残るなら、言い換えを重ねず、文や段落の組み立てごと書き直すか、理由をつけて残す

### 6. 書き出して報告する

- 書き出し先への書き込みは、その書き出し先の作法に従う。Notion などの外部システムは、差分の提示と承認を経てから書く
- 報告には次を短く添える
    - 読み手の想定
    - 既存の文書を直したときは、数の前後の比較
    - 残した指摘とその理由
    - 読み方が二通りあって決めきれなかった箇所
- 報告の文にも同じルールを当てる。点検で使った言葉をそのまま名詞にした言い方が報告に残りやすい
- スクラッチパッドに作ったファイルは、対象の文書のディレクトリへ持ち込まない

## 語の一覧を育てる

`check.py` の冒頭にある語の一覧は、指摘を受けるたびに足す。ある文書でだけ使ってよい語は一覧から外さず、手順3で理由をつけて残す。
