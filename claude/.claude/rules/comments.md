# コメント規約

コードは「どう動くか」を示す。コメントは「なぜそうしたか」だけを担う。

- 原則コメントなし。迷ったら書かない。
- コメントは日本語で書く。
- 書いてよいのは、コードだけでは伝わらない非自明な理由に限る。
  外部仕様の制約、意図的な逸脱、罠、互換性のための回避策、
  単純な書き方をあえて避けた理由。
- コードの逐語説明を書かない。処理の手順、名前や型やシグネチャの繰り返し、
  ブロックの終端マーカーはすべて禁止。
- 差分の説明を書かない。「〜に修正」「〜を追加」「指示通り〜に変更」は禁止。
  判定基準: diff を見たことがない人がこのファイルを初めて読んで意味が通るか。
  通らないならコミットメッセージに書く。
- 仕様書のセクション番号、設計ドキュメントへの参照は書かない。
  リンクを消しても内容が自立して読めること。
  チケットID、RFC、安定したパスの README は breadcrumb として可。
- 括弧書きの補足は書かない。削るか本文へ溶かす。括弧が残るのはコードの記法だけ。
- 残すコメントにも同じ基準を適用する。
  「本物の why を持っている」ことと「最短で書けている」ことは別の判定。
  正当な理由でも3倍長いことがある。5行のブロックはまず疑う。
- 公開関数やエンドポイントの1行サマリは可。自明な1行への逐語コメントはどこでも不可。
- 実装を終える前に、追加・変更したコメントを自分で見直して削る。
