# 日本語の書き方

人が読む日本語の文章を書くときの約束。社内の資料と社外発信では読み手が違うので、ルールも分ける。コードのコメントは `comments.md` に従う。リポジトリ固有の追加は各リポジトリの `.claude/rules/` に置く。

## 点検を通す場面

- 人に見せる文書を書き出す前に、writing-check スキルの点検を通す。対象は Notion、Claude Docs、Artifact、共有する Markdown、スライドの文面、長めの Slack やメールの文面
- 数行の文面とチャットの返答はスキルを呼ばず、このルールだけで書く

## 書く前に

- 読み手、使われ方（事前に読む資料か、当日に見ながら話す資料か、公開物か）、トーンを1〜2行で示し、ずれを先に直してもらう
- 指示の解釈が割れそうなときは、決めつけずに1行で確認するか、2案並べる
- 書き手が何をしたいかを先に掴む。「〜は扱わない」のような除外より、やりたいことを書く
- 主メッセージを一文で書けるか確かめる。書けないなら素材が足りていないので、何が足りないかを伝える

## 内容を足さない

- 会話、メモ、資料にない事実、数値、人名、日付、評価、方針を足さない。正しそうでも、書き手が言っていないことを書き手の言葉として広めてしまう
- 確信の度合いを変えない。「次回また相談する」を「合意した」にしない。未定は未定、推定は推定のまま書く
- 話に出ていない論点や担当を足さない。足したいときはチャットで提案する
- 人の考えや感想を推測で足さない
- 「理由は3つある」のような、元にない数の枠組みを作らない
- 元の数字が食い違って見えても黙って直さず、チャットで伝える
- 一般論しか書けない箇所は推測で埋めず、何があれば具体的に書けるかを伝える

## 直すとき

- 言い回しを直す前に、変更案を「いま／案／理由」の一覧でチャットに出し、承認を得てから直す。自分がこの場で書いた下書きを仕上げるときは、承認を待たずに直してよい
- 直さないものを先に示す。人の発言の引用、公式の文言（ミッション・ビジョン・バリューなど）、公開済みの言い回し、数字
- 直しすぎない。定着した慣用句、本人の言葉、書き手の語りかけ（「ぜひ〜ください！」）、敬語の度合い、表記の癖は残す
- 意味の通る言葉を好みで言い換えない
- 直したあと、同じ数え方で前後を比べて示す。読点で区切った見出しの本数、多用していた語の回数など

## 共通

文と段落

- 一文一意。結論の繰り返し、自明な補足、末尾の説明オチを入れない
- 前置きの宣言（「本資料では」）、次の節へ渡すためだけの一文、締めの定型句、教訓や願望で閉じる締めを入れない
- 文体（です・ます／だ・である）を文書の中でそろえる。見出し、箇条、表、図の注記のような短い項目は常体や体言止めでよい
- 単語を並べただけの断片文や「〜から〜まで。」で書き出さない
- すぐ後の引用や図の中身を前の文で言い直さない。隣の節と同じ文や数字を重ねない
- 定義文の型、節の組み立て、文の書き出しを3回続けて同じにしない。崩すためだけに体言止めや疑問形を入れない
- 短い主題のすぐ後に、間を作るだけの読点を打たない（「これは、」「課題は、」）。誤読を防ぐ読点は残す
- 推定や未確認を「〜と思われます」で全体に散らさない。断定できることは断定し、推定は推定、未確認は未確認と書き分ける

言葉

- 先回りの打ち消しや、対比の形を作るためだけの「AではなくB」を使わない。言いたいことを肯定の文で書く。誤解を正す、語の意味を絞る、注意を促す打ち消しは残す
- 比喩や擬人化で済ませず、何が起きるかを書く。「支える」「つなぐ」「届ける」「となりで」「土台」「形にする」「仕組み」のような便利な語を繰り返さない
- 調子だけを強める言葉（「徹底的に」「圧倒的に」「劇的に」「非常に」）は削る。別の強調語に言い換えない
- 動作を名詞にまとめて、誰が何をするかを消さない。「権限の整理は未着手」は「権限を誰に付けるかは決めていない」と書く。「結果の確かめ」のように動詞を名詞にした言い方は「結果の確認」か「結果を確かめる」にする
- 英語の言い方を1語ずつ訳した言葉を使わない（「真実の源」「低くぶら下がった果実」）。定着した訳語は使ってよい
- ふだん言わない語の組み合わせを作らない（「期限が終了する」は「期限が切れる」）。ふだん使う漢語（確認・通知・設定）を和語に開かない
- 「〜することができる」は「〜できる」、「〜という形で進める」は「〜で進める」と書く
- 同じものは文書の中で同じ語で呼ぶ。数字の名前や対象の呼び方を言い換えない
- ブランチ名や集計の区分名のような作業用の名前をそのまま出さない。何を指すのかを言葉で書く

見出しと装飾

- 太字は使わない。強調が本当に要る1〜2か所だけにとどめる
- 太字のラベルとコロンで始まる箇条（`- **特徴**: 〜`）を並べない。日時や担当のような値のラベルは太字なしで残し、説明文のラベルは文に溶かす
- 見出しを読点で区切る標語にしない（「〇〇を、〇〇に。」「〇〇で、〇〇する。」「AからBへ。」）。言い切りの一文か、何の節かが分かる項目名にし、引用でない見出しに句点を付けない
- 括弧に入れるのは略語の正式名称、短い言い換え、数値や出典だけにする。文や列挙になる補足は本文に書く
- ダッシュで文をつながない。絵文字は凡例のように役割があるときだけ使う

## 社内の資料

MTG資料、Notion、Claude Docs など、社内の人が読む資料。

- 箇条書きベースで区切る。中身は削らず、1項目1論点に切り分けて親子にする
- 書式は節ごとにそろえる。ある節だけ文章、ある節だけ箇条書き、にしない
- 列挙は観点をそろえ、重なりと抜けをなくす。中身を言えていない分類の見出しは作らず、中身を直接並べる
- 冒頭の「このページについて」は目次にしない。何の資料か、何が書いてあるか、どう使うかを3点ほどで書く
- 関係者が作った資料や施策への評価は断定しない。事実を挙げ、「〜しにくいかもしれない」の温度で書く
- 関係者に見せる資料に、日付、発言者、出典のメモや、当たり前のこと、「変更なし」の記載を書かない。経緯は手元の記録に置く

## 社外発信

ニュースレター、ブログ、登壇資料、採用向けの資料の本文を書くときは、書く前に `~/.claude/skills/writing-check/references/external.md` を読む。

## 育て方

- 「今後も」と言われた指摘と、2回以上受けた同じ指摘をここに足す。足し方は `~/.claude/skills/writing-check/references/maintenance.md` に従う
